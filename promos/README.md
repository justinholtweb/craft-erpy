# Plugin Store promo images

Marketing images for the Erpy listing on the Craft Plugin Store, rendered in the same theme as the
plugin's marketing page at
[justinholt.com/plugins/craft-erpy](https://justinholt.com/plugins/craft-erpy).

## Building

```bash
./build.sh          # all slides
./build.sh "2 6"    # just slides 2 and 6
```

Output lands in `out/` as `erpy-promo-N.jpg`, 1920×1080 (rendered at 2× in headless Chrome, then
downsampled and converted to JPEG in one `sips` pass). Promos ship as JPEG, never PNG.

Chrome occasionally dies with a `Trace/BPT trap` partway through a full run. It is transient and
the script uses `set -e`, so re-run the slides it did not reach rather than assuming a real failure.

Slides 8–11 are **real control-panel screenshots**, not mockups. They come from the plugin-testing
harness running the built-in Mock ERP against two seeded connections — which is why the matrix says
"Mock ERP" rather than a vendor name. Re-take them with `plugin-shots/specs/erpy.json`:

```sh
cd ~/Sites/plugin-shots
CP_BASE=https://plugin-testing.ddev.site:33001 node capture.mjs out/erpy specs/erpy.json
```

`erpy-sync.png` and `erpy-activity.png` in `shots/` are cropped out of taller captures with
`sips -c <h> <w> --cropOffset <y> 0`; the raw versions are the full `#content` element.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette and fonts
are the plugin site's: accent `#2F8F55`, Jersey 20 for display, Inter for body. The green is
deliberately a *warmer* green than Abacus's `#2b8a6f`, so the two decks do not read as the same
product at thumbnail size.

`assets/` holds the fonts and the icons, all written by `icon-gen.py` — don't edit them by hand:

- `icon.svg` — the app icon, a copy of `../src/icon.svg`.
- `watermark.svg` — the glyph **with the tile stripped off** and cropped so the spokes run off the
  edge; a tile at watermark scale is a hard-edged green box behind every slide. It is drawn at 3%
  opacity because the glyph is solid. The cover suppresses it (`.cover::after { display: none }`).
- `addons/<vendor>.svg` — the twelve add-on icons, for slide 3.

**`.rule` is already taken.** The shared sheet uses it for the eyebrow's hairline, so the mapping
rows on slide 5 are `.maprule`. A generic name added to this sheet will silently restyle something
three slides away — that is exactly how the eyebrow briefly became a filled square.

**The terminal bleeds off the right edge on purpose** (`.term { right: -110px }`), so a long line
is cut without warning rather than wrapping. Keep console output under about 44 characters.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.

## The icons

`icon-gen.py` writes the whole family: Erpy's `../src/icon.svg`, `../src/icon-mask.svg` and the two
assets above, and every add-on's `src/icon.svg` and `promos/assets/icon.svg`.

```sh
python3 icon-gen.py            # write every icon into its repo
python3 icon-gen.py /tmp/icons # or somewhere else, to preview
```

Erpy follows the family icon standard: 100×100 viewBox, a flat `#2A6B4C` tile at `rx="22.44"`, and a
`#FEFEFE` glyph made only of filled geometry (holes are `fill-rule="evenodd"`), so the CP mask is the
same glyph with the tile removed. The glyph is a hub wired to eight nodes — one engine every system
plugs into — with the exchange arrows inside it. `../src/icon.jpg` was the original concept art.

An add-on icon is Erpy's icon plus a triangle in the bottom-left corner, in the ERP's colour,
carrying its mark. The bottom-left spoke runs into the triangle, so the connector reads as plugged
in. Each mark is fitted by a small search for the largest box that keeps a margin inside both the
hypotenuse and the tile's rounded corner. The marks are in `icon-marks/marks.json`, lifted from each
vendor's published logo (or Simple Icons) by `icon-marks/extract_logos.py`; `icon-marks/bbox.json`
holds their bounding boxes, measured in Chrome with `icon-marks/bbox.html`. AFAS only publishes a
raster logo, so its wordmark is set in Arial Black and slanted.

## The add-on decks

Every add-on's `promos/` is generated from `addons/`:

```sh
python3 addons/generate.py              # all twelve
python3 addons/generate.py sage odoo    # just these
cd ../../craft-erpy-sage/promos && ./build.sh
```

Seven slides each. Slide 2 (what it syncs) and slide 3 (the connection form) come from
`addons/connectors.json`, which is dumped from the connectors themselves, so a slide can never claim
a flow the connector does not declare. Refresh it whenever a connector's `capabilities()` or
`settingsFields()` change:

```sh
cd ~/Sites/plugin-testing
ddev exec php /var/www/craft-erpy/tests/tools/dump-connectors.php > ../craft-erpy/promos/addons/connectors.json
```

The rest of the copy — tagline, three vendor traps, a mapping example — is in `addons/decks.json`.
